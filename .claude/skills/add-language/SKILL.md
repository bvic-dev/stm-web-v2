# Add Language — Sport Track Merger Web (Astro)

Skill for cleanly adding a new language to the `sporttrackmerger.com` website. Strict scope: **Astro site only**.

## See also (other skills to invoke in the right order)

Adding a language to STM touches **3 repos**. This skill only covers the website. For the other parts, invoke the matching skills:

- 📱 **Mobile app (KMP)**: `stm-kmp/.claude/skills/add-language/SKILL.md` — strings.xml, SupportedLang enum, Android/iOS locales config, FirebaseRemoteConfigRepository.
- 🔥 **Firebase Remote Config**: `firebase-fonctions/.claude/skills/add-language/SKILL.md` — `remoteconfig/{debug,prod}.template.json` files + deployment with `./scripts/deploy-remoteconfig.sh`. URLs defined in Remote Config must match the routes generated by this site.

**Logical deployment order**: this site **first** (pages must exist before Firebase Remote Config points to them, otherwise 404 in the mobile app), then Remote Config, then the mobile app.

## ⚠️ Regional variants: `xx` vs `xx-yy` convention

First, determine if the new language has relevant regional variants (PT/BR, ZH-CN/ZH-TW, ES-ES/ES-MX, EN-US/EN-GB, etc.). **Universal convention** followed by Strava, Apple, Google:

- `xx` (no suffix) = **majority** variant worldwide (= default fallback). For Portuguese: `pt` = PT-BR.
- `xx-YY` = **explicit** variant (e.g. `pt-pt` = European Portuguese, `zh-tw` = Traditional Chinese).

**On the Astro side**: you can have `/pt-pt/`, `/pt-br/`, `/pt/` separately in `LOCALES` (each = its own route and `i18n/<key>.json` file). Recommended convention: lowercase + hyphen (`pt-pt`, `pt-br`, `zh-tw`).

**Current STM state (May 2026)**:
- `pt-pt` exists (PT-PT, aligned with Strava `pt-PT`)
- `pt-br` to be created later (PT-BR, aligned with Strava `pt`)
- ⚠️ No generic `pt` for now. Add it later if you want a generic fallback for non-PT-PT lusophone users.

**Web language picker**: if multiple variants coexist, distinguish them with both flag **and** country label: `🇵🇹 Português (Portugal)` + `🇧🇷 Português (Brasil)`. Don't use plain "Português" twice.

## i18n architecture of the site

- **Native Astro i18n** (Astro 5+, no external dependency).
- **Routing**: `prefixDefaultLocale: true` → all routes are prefixed (`/en/`, `/fr/`, etc.).
- **Dynamic pages**: `src/pages/[lang]/*.astro` use `generateLangStaticPaths()` which iterates over `LOCALES_KEYS`. **Once `config.ts` is updated, all `/<key>/*` routes exist automatically**.
- **Content**: 1 JSON file per language in `src/i18n/<key>.json` (~180 lines) + 3 markdown files in `src/content/<key>/mobile/` (legal pages).
- **Assets**: App Store / Play Store badges per language in `src/assets/badges/<key>/`.

## Prerequisites: information to gather

| Variable | Example `pt-pt` | Example `it` | Example `zh-tw` |
|---|---|---|---|
| Routing key (= folder/URL) | `pt-pt` | `it` | `zh-tw` |
| Endonym | `Português (Portugal)` | `Italiano` | `繁體中文` |
| Flag emoji | 🇵🇹 | 🇮🇹 | 🇹🇼 |
| App Store code (URL segment) | `pt` | `it` | `tw` |
| Play Store code (`hl=`) | `pt-PT` | `it` | `zh-TW` |
| Index in `LOCALES` | `4` (after `es=3`) | etc. | etc. |

⚠️ **App Store code ≠ ISO language code always**: Apple uses **country** codes in URLs (`/us/`, `/fr/`, `/pt/`, `/br/`, `/tw/`). Verify on https://apps.apple.com by manually navigating in the target country.

⚠️ **Play Store code**: `hl=<lang-tag>` is almost always valid. For regional variants, use the full tag (e.g. `hl=pt-PT`, `hl=zh-TW`).

## File modifications (9 touchpoints)

### 1. `src/config.ts` — declare the language

Add an entry to the `LOCALES` array (the order determines the order in the language picker):

```typescript
export const LOCALES = [
  { key: "en", index: 0 },
  { key: "fr", index: 1 },
  { key: "de", index: 2 },
  { key: "es", index: 3 },
  { key: "<key>", index: <N> },  // ← add
] as const;
```

This is the **single change** that unlocks everything else: Astro i18n, routing, language picker, sitemap.

### 2. `astro.config.mjs` — exclude noindex pages from the sitemap

Add 4 lines to the `sitemap` filter:

```javascript
filter: (page) =>
  // ... other languages ...
  page !== SITE_URL + '/<key>/auth/strava/callback/' &&
  page !== SITE_URL + '/<key>/mobile/cgu/' &&
  page !== SITE_URL + '/<key>/mobile/cgv/' &&
  page !== SITE_URL + '/<key>/mobile/privacy/',
```

⚠️ Without these 4 lines, the sitemap will expose legal pages and the Strava callback to Google → bad SEO + duplicate legal content across languages.

### 2b. `public/robots.txt` — disallow noindex pages for the new locale

Add 4 `Disallow` lines for the new locale (mirroring the existing `/en/...`, `/fr/...` entries):

```
Disallow: /<key>/auth/strava/callback/
Disallow: /<key>/mobile/cgu/
Disallow: /<key>/mobile/cgv/
Disallow: /<key>/mobile/privacy/
```

⚠️ The `<meta robots="noindex,nofollow">` already on these pages prevents indexation, but `robots.txt` also blocks **crawling**, which saves crawl budget and prevents Google from spending requests discovering pages it shouldn't index. Both layers are needed for clean SEO hygiene.

### 3. `src/i18n/<key>.json` — create the translation file

Procedure:
1. Copy `src/i18n/en.json` (English reference, ~180 lines)
2. Translate **all** values (keys stay unchanged)
3. **Specifically adapt**:

#### `nav.languages` — flag + endonym with country if regional variant

```json
"languages": [
  { "label": "🇬🇧 English" },
  { "label": "🇫🇷 Français" },
  { "label": "🇩🇪 Deutsch" },
  { "label": "🇪🇸 Español" },
  { "label": "🇵🇹 Português (Portugal)" }
]
```

#### `nav.themes` — translated labels
Translate `Auto`, `Sombre/Dark/Dunkel/Oscuro`, `Clair/Light/Hell/Claro` according to the language.

#### `storeBadges.playstore_url` and `storeBadges.appstore_url`
```json
"storeBadges": {
    "playstore_url": "https://play.google.com/store/apps/details?id=com.bvic.sporttrackmerger&hl=<play-tag>",
    "appstore_url": "https://apps.apple.com/<apple-region>/app/sport-track-merger/id6736858288"
}
```

#### `footer.copyright` — preserve the `{year}` placeholder

#### `faq.questions` — array of 13 question/answer pairs to translate fully

### 4. All existing `i18n/*.json` — propagate the flag

The language picker reads `nav.languages[index]` from the current JSON. So in **each** existing file (`en.json`, `fr.json`, `de.json`, `es.json`, `pt-pt.json`, etc.), add to the `nav.languages` array (at the same index `N`):

```json
{ "label": "🇵🇹 Português (Portugal)" }
```

⚠️ Convention of this app: language names in `nav.languages` are endonyms (the name in the language itself), so identical everywhere.

### 5-7. Legal markdown (`src/content/<key>/mobile/{cgu,cgv,privacy}.md`)

Procedure for each file:
1. Copy the equivalent version from another language (e.g. `src/content/en/mobile/cgu.md`)
2. Keep the YAML frontmatter exactly with its `head` and `title` fields
3. Translate the markdown preserving structure (h2, lists, blockquotes, frontmatter)
4. Preserve the `**Last updated: MM/DD/YYYY**` format (or its translated equivalent)

⚠️ These files mention GDPR — important that the translation stays legally accurate. Recommendation: review or have it reviewed by a native speaker.

### 8. `src/assets/badges/<key>/` — create folder + 2 SVG badges

Two SVG files to create:
- `google_badge.svg` — official "Get it on Google Play" badge
- `ios_badge.svg` — official "Download on the App Store" badge (Black lockup)

Both are loaded by [src/components/StoreBadges.astro](../../../src/components/StoreBadges.astro) via Astro's SVG-as-component import:
```astro
const AppleLogo = (await import(`../assets/badges/${lang}/ios_badge.svg`)).default;
const GoogleLogo = (await import(`../assets/badges/${lang}/google_badge.svg`)).default;
```
Both badges are rendered as `<Logo height={logoHeight} />` — only `viewBox` should be on the SVG element (no baked `width` / `height` attributes), so the badge can scale freely from the `height` prop.

⚠️ **Apple's official SVGs ship with `width="119.66407"` and `height="40"` attributes baked in** — these MUST be stripped after copying, otherwise the SVG is locked to its native size (40px tall) regardless of the `height` prop. CSS workarounds don't work cleanly: an SVG's HTML `width` attribute defines its intrinsic dimension, and CSS `width: auto` then resolves to that intrinsic value rather than overriding it.

```bash
# After copying Apple SVGs, strip the size attributes:
for lang in en fr de es pt-pt; do
  sed -i '' 's/ width="[0-9.]*"//; s/ height="[0-9.]*"//' "src/assets/badges/$lang/ios_badge.svg"
done
```

Google SVGs don't have this issue (no baked width / height), so they work as-is.

#### Preferred source: parent directory bundles

Official asset bundles **may already be downloaded** in the parent directory `Code/`:
- `Code/Google Play Badge guidelines/Get it on Google Play Badges/Digital/svg/GetItOnGooglePlay_Badge_Web_color_<Language>.svg` (e.g. `_French.svg`, `_Portuguese-Portugal.svg`, `_German.svg`, `_Spanish.svg`, `_English.svg`)
- `Code/Download-on-the-App-Store/<COUNTRY>/Download_on_App_Store/Black_lockup/SVG/*.svg` (e.g. `US/`, `FR/`, `DE/`, `ES/`, `PTPT/`)

**If these folders exist, copy the SVGs from them — they cover ~all locales and are already at the same brand version (consistency).** Only fall back to manual download if the language is missing from the bundles.

```bash
# Example for adding "it" (Italian)
cp "../Google Play Badge guidelines/Get it on Google Play Badges/Digital/svg/GetItOnGooglePlay_Badge_Web_color_Italian.svg" \
   src/assets/badges/it/google_badge.svg
cp ../Download-on-the-App-Store/IT/Download_on_App_Store/Black_lockup/SVG/*.svg \
   src/assets/badges/it/ios_badge.svg
```

#### Fallback: manual download (if bundles unavailable or language missing)

- **Google Play**: https://partnermarketinghub.withgoogle.com/brands/google-play/visual-identity/badge-guidelines/ → choose the language → download SVG (URLs are signed and expire in 24h, so no scriptable download possible)
- **Apple App Store**: https://developer.apple.com/app-store/marketing/guidelines/ → "Download on the App Store" badge → choose the language → download SVG

⚠️ If the target language has no official badge, use the English one (acceptable per brand guidelines). Do NOT create a custom badge.

## No page modification needed

Pages in `src/pages/[lang]/*.astro` all use `generateLangStaticPaths()` (defined in `src/utils/locale.ts`) which iterates over `LOCALES_KEYS`. Once `config.ts` is updated, **all** routes below are generated automatically:

`hreflang` tags are also generated automatically by `BaseLayout.astro` via `getAbsoluteLocaleUrl()`.

## Pitfalls

| Issue | Symptom | Fix |
|---|---|---|
| Forgot the sitemap filter | Legal / callback pages indexed by Google | Add the 4 lines in `astro.config.mjs` |
| Forgot the `robots.txt` Disallow lines | Google wastes crawl budget discovering noindex pages | Add 4 `Disallow` lines for the new locale in `public/robots.txt` |
| Flag at the wrong index | Picker shows the wrong language name | Make sure `index` in `config.ts` matches the position in `nav.languages` of ALL JSON files |
| Forgot `nav.languages` in another language | From that language, the new language doesn't appear in the picker | Add the entry at the same index in EACH existing JSON |
| Missing markdown pages | Astro build fails (`Cannot find module ../../../content/<key>/mobile/cgu`) | Create the 3 `.md` files in `src/content/<key>/mobile/` |
| Missing badges folder | Build fails (`Cannot find module ../assets/badges/<key>/ios_badge.svg` or `google_badge.svg`) | Create the folder + copy 2 SVGs from `Code/Google Play Badge guidelines/` and `Code/Download-on-the-App-Store/` (or fall back to `en/`) |
| Apple badge doesn't scale up to `logoHeight` | Apple badge stuck at 40px tall regardless of `height` prop | Apple official SVGs have `width="119.66407"` and `height="40"` baked in — strip both attributes from each `ios_badge.svg` (only keep `viewBox`). CSS `width:auto` does NOT work because the SVG attribute defines intrinsic size |
| Mishandled JSON special characters | Build fails (`Unexpected token in JSON`) | Properly escape quotes (`\"`) — use a JSON linter |
| App Store URL without the right language | The badge leads to the English page | Verify the country segment in the URL, manually browse apps.apple.com |
| URL slug `/pt_pt/` instead of `/pt-pt/` | Unexpected routes, mismatch with Remote Config | Convention: lowercase hyphen (`pt-pt`, `zh-tw`), not underscore |
